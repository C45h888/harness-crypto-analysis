## Behavioral notes

### PredictStrategy contract

**Initialization** — `PredictStrategy(config: PredictConfig | None = None)` (line 70). If `config` is `None`, a fresh `PredictConfig()` is instantiated lazily inside `__init__` to avoid import cycles. The config controls `max_retries` (default 10), `max_error_chars` (default 1000), `max_param_chars` (default 200_000; `None` disables the parameter-size guard), sampling params (`max_tokens`/`temperature`/`top_p`), and `output_serialization` (default `"event"`; alternative `"tool_call"` replaces the `LLMOutput` event with a synthetic `return_result` `ToolCallEvent`). Both `preconditions` and `postconditions` are declared on `PredictConfig` but the source comment notes that Pydantic-wiring of those validators into `PredictStrategy` "lands with the full validator MR, !444" — currently consumed only by `CodeActStrategy`. `UNVERIFIED — requires B-lane` for whether postcondition wiring is functional in `PredictStrategy` at runtime today.

**Decorator expectations** — agent methods decorated with `@strategy(PredictStrategy(...))` MUST have a return type annotation. Supported annotation shapes (per `_create_response_model` at line 720): Pydantic `BaseModel` subclasses (used directly, optionally stripping `@hidden` fields into a `*Public` model), `dict` / `dict[K, V]` (rendered as `RootModel`), `Optional[T]` / `Union[T, None]` (unwrapped to `T`), basic types `str`/`int`/`bool`/`dict`/`list`, nested generics, and lists/tuples/sets (wrapped in a model with a `value` field so the JSON-schema root is an object — the Responses API rejects array-rooted schemas, see issue 232). Non-JSON-serializable types such as `pandas.DataFrame` / `numpy.ndarray` (including Pydantic models that contain such fields) raise a clear `GenerationError` from `model_json_schema()` failure at line 224–234.

**Returns** — the validated result matching the method's declared return type. For Pydantic models: the model instance (or a re-built instance of the original class via `_agentdoc_original_model`). For `RootModel[dict[K,V]]`: the unwrapped root value. For wrapped basic types: the unwrapped `.value` attribute. On success, `BeforeTurn`/`AfterTurn` (single turn, `turn_number=1`, `is_final=True`) events are emitted regardless of outcome (`record=False` so they do not enter replay history).

**Tolerates / rejects** — tolerates: media (`Media`) parameters attached to the call (converted to multimodal content blocks); structured output in `content` (preferred) or `reasoning` (fallback with metric `content_to_reasoning_fallback`); XML wrappers around the LLM response (`_strip_xml_wrapper`); Pydantic `ValidationError`, `json.JSONDecodeError`, `ValueError`, `TypeError` — each triggers a retry with descriptive error feedback via `@strategy(TemplateStrategy())`-decorated helpers (`error_pydantic_validation`, `error_type_validation`, `error_json_parsing`). Rejects: methods with no return type annotation (raises `GenerationError`); `type(None)` as return type (raises `GenerationError`); oversized parameters exceeding `max_param_chars` (raises `ValueError` before any LLM call). After `max_retries` validation attempts, raises `GenerationError` with all failed-attempt metadata attached to the current OpenTelemetry span (`predict.failed_attempt_{N}.raw_output`, `.error_type`, `.error_message`).

### CodeActStrategy contract

**Initialization** — `CodeActStrategy(config: CodeActConfig | None = None, *, error_formatter: IPythonErrorFormatter | None = None)` (line 298). Both args are keyword-friendly; the `error_formatter` defaults to `IPythonErrorFormatter` and accepts any object exposing `format(error, code) -> str` (the `line_offset` keyword is optional — handled with a `TypeError` fallback). Config controls: `max_iterations` (default `None` = unbounded), `max_retries` (default 3), `max_consecutive_text_only` (default 3; `0` disables the guard), `text_only_stop_behavior` (`"return_result"` default or `"synthetic_comment"` — the deprecated `"synthetic_reasoning"` is auto-migrated to `"synthetic_comment"`), `cell_timeout`, sampling params, `max_tool_calls`, `translate_tool_calls` (default `False`; converts unknown tool calls into `execute_python` code), `restrictions` (`RestrictionsConfig`), `execution_backend` (`"inprocess"` default or `"sandbox"` — sandbox uses `SandboxedExecutor` with OS-enforced guardrails and a hard `cell_timeout`), `sandbox` (`SandboxConfig`), `preconditions`/`postconditions` (deterministic invariants run before generation / after return-type validation — see `nooa.strategy_validation`; raise `InvariantError` for model-correctable retry feedback, any other exception propagates as infrastructure error), and `prefill` (default `InspectInputsPrefill()`; `None` disables; custom `Prefill` protocol instance replaces). `UNVERIFIED — requires B-lane` for sandbox execution semantics across providers — the file claims OS-enforced guards but only local behavior was read here.

**Decorator expectations** — agent methods decorated with `@strategy(CodeActStrategy(...))` MUST have a return type annotation; the type drives the `return_result` tool's Pydantic schema via `_create_return_model` (line 2172) and `_build_return_result_tool` (line 2256). Types that fail `_is_pydantic_compatible` (e.g. `pd.DataFrame`, `np.ndarray`, classes without Pydantic support, or models with non-JSON-serializable fields) fall back to an `Any` schema and get a verbose description that includes `doc(return_type)` rendering — instructing the model to construct the object in `execute_python` and call `return_result(variable)` from within the code rather than via the tool. `Annotated[T, "description", ...]` annotations are promoted to `Field(description=...)` on the wrapper model. For `-> None` return type, the tool schema accepts no required result. The agent must call `execute_python(code)` and/or `return_result(value)` each turn — bare text does not end the session; calling `return_result(value)` is the canonical completion path.

**Returns** — the validated result matching the method's declared return type. Completion paths: (a) explicit `return_result(...)` tool call passes through `_handle_return_result` (line 1689); (b) inline `return_result(value)` from inside `execute_python` raises `_ReturnResultSignal` which the executor catches (line 1524); (c) explicit Python `return <value>` statements that validate against `return_type` auto-complete (line 1610) via `_try_validate_return_value`. All three paths emit a synthetic `return_result` `ToolCallEvent` with `metadata.synthetic_type = "codeact_inline_return"` (line 1877) for trajectory observability. `BeforeTurn`/`AfterTurn` events are emitted around each turn (`turn_number` increments per iteration; `is_final=True` only on the terminal turn).

**Tolerates / rejects** — tolerates: text-only responses (`finish_reason="stop"` no tool call) routed by `text_only_stop_behavior` — `"return_result"` mode synthesizes a `return_result` tool call from the text content and routes it through validation (resilient to benign drift, recovered drift is marked `recovered=True` on the `TextOnlyReply` event); `"synthetic_comment"` mode converts the text to an `execute_python` `#`-comment no-op. Tolerates: LLM calling `return_result(field1=..., field2=...)` (auto-wrapped under `"result"`, metric `args_normalized`); GPT-4o-mini double-quoted strings (auto-unwrapped, metric `gpt4o_double_quote_fix`); variable-name references in `return_result` tool args (resolved from `session.session_locals`, metric `variable_ref_resolved`); JSON/Python-literal strings auto-parsed (metric `json_auto_parsed`); constructor-call strings like `Foo(x=1)` (evaluated in session namespace, metric `constructor_string_coerced`); unknown tool calls translated to `execute_python` when `translate_tool_calls=True` (metric `tool_call_translated`). Tolerates: `BlockSyntaxError` from context-block LLM output (removes the bad block, adds error feedback, records as iteration not error — line 1364). Tolerates: empty LLM API responses (records error, adds feedback via `_tool_use_reminder`); `finish_reason="length"` aborts immediately with actionable `max_tokens` guidance (line 1095–1104). Rejects: methods with no return type annotation (raises `GenerationError`); `max_retries` consecutive errors (raises `GenerationError` with cause chain); `max_iterations` reached without success (raises `GenerationError`); `max_consecutive_text_only` exceeded (raises `GenerationError`, metric `text_only_loop_abort`); LLM API errors after retries exhausted (raises `GenerationError`); preconditions that raise non-`InvariantError` exceptions (wrapped as `RuntimeError`); sandbox backend when guardrails cannot be enforced at session-init (fails closed before any cell).

## Suggested remediation

- `PredictStrategy` declares `preconditions` / `postconditions` fields on `PredictConfig`, but the source comment (`strategy_config.py:142-143`) explicitly says Pydantic-wiring of those validators into `PredictStrategy` "lands with the full validator MR, !444". If our codebase passes `PredictConfig(postconditions=[...])` to `PredictStrategy` expecting runtime enforcement, that contract is currently dead — only `CodeActStrategy` consumes them. Either confirm the MR is shipped in the version we depend on, or restrict usage to `CodeActStrategy` only.
- `PredictStrategy.execute` and `CodeActStrategy.execute` both assume `runtime.event_manager`, `runtime.generate`, `runtime.truncation_config`, `runtime.get_generation_id()`, and `runtime.get_parent_generation_id()` are all non-None; `_run_generation` raises `RuntimeError` if `get_generation_id()` is `None`, but `_execute_inner` does not guard `get_generation_id()` defensively. If our integration wraps `runtime` in test doubles that return `None` for generation IDs, `PredictStrategy` will silently emit events with empty IDs rather than failing fast.
- `CodeActStrategy._maybe_eval_constructor_string` uses bare `eval()` on LLM-supplied strings against a constrained namespace — defended only by `{"__builtins__": {}}` and a `TypeError`/`ValueError`/`SyntaxError` catch. The LLM can still construct arbitrary objects of any class reachable via `session.session_locals` or `return_type`. This is intentional for fan-out workflows but should be reviewed against our threat model (LLM-supplied code is already evaluated, so the marginal exposure is small).
- `CodeActLiteStrategy.execute` mutates `runtime.agent.render_config` for the duration of the call; if a strategy error interrupts between the assignment and the `finally` block, the config is restored — but a `BaseException` from `super().execute()` that the runtime suppresses could leak the modified config. The pattern is wrapped in a `try/finally`, so this is safe in CPython; `UNVERIFIED — requires B-lane` for any `greenlet`/`gevent` runtime that doesn't honor `try/finally` semantics.
- `PredictStrategy._create_response_model` strips `@hidden` fields from the Pydantic model sent to the LLM, but `_validate_response` rebuilds the *original* type via `model_dump()`. If the original model has validators tied to hidden fields, those will not run on the LLM-supplied result. Document or test this for any agent whose Pydantic return type uses `@hidden` extensively.
- `ReflexionConfig` is present in `strategy_config.py` but `ReflexionStrategy` is not part of the strategy files we were given; the docstring flags it as deprecated. If our codebase has lingering `@strategy(ReflexionStrategy(...))` decorators, they will fail at import.
